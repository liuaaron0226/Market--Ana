# 基金淨值缺口：自己動手補（不需要助手）

## 什麼時候要用到

平常不用管。網站每天自動從集保開放資料抓基金淨值，有兩個地方會抓：

- **announcements**：每天台北 08:00（含週末、連假）。
- **daily-update**：週一到週五 15:30、16:30、18:00、20:30。

兩邊共用一個「今天抓過了」的記號，先抓成功的那一邊抓，另一邊當天不再抓；抓失敗不留記號，下一個時段會再試。
集保開放資料只留**最近 4 個淨值日**（2026-11-24 實測：當天只有 11-16～11-19 四天），所以兩邊都**連續 4 個營業日以上**沒抓成功，中間那幾天就永遠抓不回來了，這時候才要照下面的步驟手動補。

## 怎麼知道有缺口

GitHub → 這個專案 → **Actions** → 點最新一次的 **announcements** 或 **daily-update** → 往下看執行摘要的「**基金淨值**」：

- 寫「正常」：不用做事。
- 寫「抓取失敗 …（下一個排程時段會再試）」：先不用做事，等下一個時段。
- 寫「**XXX（基金名）缺淨值 2026-11-17～2026-11-18（2 個平日沒有任何官方檔看過）**」：就是這份說明要處理的情況。記下**站上代碼**（例如 `GLIACU`）和**日期範圍**。

| 站上代碼 | 集保代碼（網址用） | 基金 |
|---|---|---|
| `BLKTENAU` | `BLKTENAU` | 貝萊德世界科技基金 A10美元(總報酬穩定配息) |
| `AGIFFVM` | `AGIF-FVM` | 安聯收益成長基金-AM穩定月收類股(美元) |
| `GLIACU` | `GLIACU` | 摩根多重收益(美元對沖) A股(穩定月配) |

## 步驟

### 1. 到集保網頁讀出缺的那幾天

用一般瀏覽器打開（把 `<集保代碼>` 換成上表的集保代碼）：

`https://www.fundclear.com.tw/fund-basic-info?site=offshore&key=<集保代碼>&tab=fund-nav`

期間選能涵蓋缺口的那一個（例如「一個月」），把**缺口範圍裡每一天**的日期和淨值抄下來（數字照網頁上的照抄，不要四捨五入）。
那幾天裡如果有某個平日網頁上就是沒有淨值，代表基金那天休市，**不要自己編一個數字**。
遇到驗證碼就停下來，不要想辦法繞過（本人 2026-11-17 定的規則）。

### 2. 做一個淨值檔

在 `seeds/funds/<站上代碼>/` 資料夾新增一個純文字檔，檔名接著現有的編號：第一次補叫 `nav-backfill-2.csv`，下一次 `nav-backfill-3.csv`，以此類推（原本的 `nav-backfill.csv` 不要動）。

內容一天一行，`日期,淨值`，日期由舊到新，**不要標題列**、不要空白：

```
2026-11-17,70.410000
2026-11-18,70.190000
```

用記事本存檔沒關係（存成 UTF-8；有沒有 BOM、換行是 Windows 還是 Mac 的都讀得懂）。**存好以後就不要再改**，改一個字下一步的指紋就對不上。

### 3. 算這個檔的 SHA-256（檔案指紋）

SHA-256 是用檔案的每一個位元組算出來的 64 個字的指紋。網站每次建置都會重算一次、和清單上記的比：一樣才用；**不一樣就整檔基金停用**（不拿被改過的檔算），執行摘要會出現「回補原件 … 的 SHA-256 和清單不符，停止」。

- Windows：在檔案所在資料夾開 PowerShell，打
  `Get-FileHash .\nav-backfill-2.csv -Algorithm SHA256`
  複製 `Hash` 那一欄（大寫也可以）。
- Mac：終端機打 `shasum -a 256 nav-backfill-2.csv`，複製前面那串。

### 4. 把這個檔登記到清單

打開同一個資料夾的 `backfill-manifest.json`，在 `"files": [ … ]` 的**最後一筆後面**加一個逗號，再貼上這一筆（照實改內容）：

```json
    {
      "file": "nav-backfill-2.csv",
      "kind": "nav",
      "page_url": "https://www.fundclear.com.tw/fund-basic-info?site=offshore&key=GLIACU&tab=fund-nav",
      "page_action": "人工補缺口：期間點「一個月」，照網頁抄 2026-11-17～2026-11-18",
      "read_at": "2026-12-10T09:00:00+08:00",
      "first": "2026-11-17",
      "last": "2026-11-18",
      "sha256": "第 3 步複製的那串"
    }
```

- `first`／`last`：你在網頁上**看過的**第一天和最後一天（就是缺口範圍）。中間某個平日網頁沒有淨值＝基金休市，不會再被當成缺口。
- 檔裡的日期都要落在 `first`～`last` 之間，不然會停下來報錯。

### 5. 存回 GitHub

把這兩個檔（新的 `.csv`、改過的 `backfill-manifest.json`）提交推上 `main`。注意：推上 `main` 隔天的每日更新就會用新程式與資料上線。

### 6. 確認補好了

隔天看 Actions 執行摘要的「基金淨值」：

- 「正常」或那段缺口不見了 → 完成。
- 還剩幾天缺 → 那幾天沒抄到，回第 1 步補（另開下一個編號的檔）。
- 出現「SHA-256 和清單不符」→ 檔案存好後又被改過，或指紋貼錯：重算第 3 步、改清單。
- 出現「… 的淨值兩份官方檔不同」→ 你抄的某天和已經有的數字不同：網站**保留原本的**、不會被覆蓋，請回網頁核對是哪邊抄錯。

## 不要做的事

- 不要用前後兩天推算、內插或複製數字填空；沒有官方數字的日子寧可留著缺口。
- 不要改舊的 `nav-backfill.csv` 或舊的抽取檔；新的數字一律另開新檔、登記在清單最後。
- 不要用程式去打集保網站背後的資料介面、不要破解驗證碼（本人 2026-11-17 定案）。
